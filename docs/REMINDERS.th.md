# อีเมลแจ้งเตือนเข้าร่วมโครงการ

ระบบเก็บอีเมลหลังช่องชื่อ-นามสกุล และใช้ Google Apps Script MailApp ส่งอีเมลแยกถึงผู้ลงทะเบียนแต่ละคน ไม่มีการส่งทันทีหลังลงทะเบียน และไม่รวมรายชื่อผู้อื่นใน To/CC/BCC

กำหนดส่ง **20 พฤศจิกายน 2569 เวลา 09.30 น. เวลาไทย (Asia/Bangkok)** ตรงกับ `2026-11-20T02:30:00Z` ใช้ trigger แบบระบุ Date โดยตรง และมีรอบตรวจซ้ำ 09.40 น. รายการที่ส่งแล้วจะไม่ส่งซ้ำ ทั้งนี้ Apps Script และระบบอีเมลอาจเริ่มส่ง/นำส่งล่าช้ากว่าเวลานัดหมาย จึงไม่รับประกันถึงกล่องจดหมายตรงวินาที

## เปิดใช้งาน

1. ตรวจเนื้อหาอีเมลด้วยฟังก์ชัน `previewReminderEmail` ซึ่งแสดงตัวอย่างใน Execution log และไม่ส่งอีเมล
2. โค้ด `Code.gs` รุ่น 1.2 เพิ่มฟังก์ชันส่งอีเมลและตั้งเวลา หากใช้ manifest แบบระบุ scope ให้อัปเดต `appsscript.json` จากโครงการด้วย
3. บัญชีเจ้าของ Apps Script ต้องอนุญาตการใช้ Sheets, ส่งอีเมล และสร้าง time-driven triggers ในหน้า Google ให้ผู้จัดตรวจแอปและสิทธิ์ก่อนอนุญาต ไม่ส่งรหัสผ่าน/OTP/secret ในแชต
4. เลือก `setupEmailReminder` แล้ว Run หนึ่งครั้ง **ก่อนวันที่ 20 พฤศจิกายน 2569 เวลา 09.30 น.** ฟังก์ชันนี้ไม่ส่งอีเมลทันที แต่เพิ่มหัวตาราง J–N ตรวจ quota และสร้าง trigger 2 รายการสำหรับ `sendScheduledReminders`
5. เปิดหน้า Triggers ตรวจว่ามีรายการของฟังก์ชันดังกล่าว 2 รายการ และ Script Properties มี `REMINDER_ENABLED=true`, `REMINDER_SCHEDULE=2026-11-20T09:30:00+07:00`
6. Deploy Web App เป็น New version ที่ URL เดิม จากนั้นเผยแพร่หน้าเว็บ/API รุ่นใหม่ให้ใช้ schemaVersion 2 พร้อมกัน

ผู้ส่งคือบัญชีเจ้าของ trigger ที่อนุญาต MailApp ใช้ชื่อแสดง SCiUS NU Training RSVP การอนุญาตเพิ่มต้องทำโดยเจ้าของบัญชี ไม่มีการฝัง token หรือ credentials ในหน้าเว็บ

## รายการเดิมและคอลัมน์ใหม่

เก็บ A–I เดิมไว้ตามเดิม ไม่เลื่อนตำแหน่งข้อมูล รหัสภายในยังใช้ยืนยันการส่งซ้ำ แม้ไม่แสดงบนหน้าสำเร็จ

| คอลัมน์ | ข้อมูล |
| --- | --- |
| J | อีเมล |
| K | สถานะอีเมลเตือน |
| L | ส่งอีเมลเตือนเมื่อ (เวลาไทย) |
| M | พยายามส่งเมื่อ (เวลาไทย) |
| N | หมายเหตุอีเมลเตือน |

ผู้ลงทะเบียนก่อนเพิ่มช่องอีเมลจะมี J ว่าง ผู้จัดต้องเติมอีเมลที่ได้รับจากเจ้าตัวลง J ก่อนกำหนดส่ง ไม่เดาอีเมล และไม่ให้กรอกชื่อเดิมซ้ำเพื่อสร้างแถวใหม่ หาก K เป็น MISSING_EMAIL/INVALID_EMAIL แล้วผู้จัดแก้ J ให้ถูกต้อง ให้เปลี่ยน K เป็น PENDING หลังตรวจแล้วเท่านั้น

สถานะ PENDING รอส่ง, SENDING เริ่มส่ง, SENT ส่งผ่าน MailApp แล้ว (ไม่ใช่การยืนยันว่าถึง inbox), ERROR ต้องตรวจสอบ, MISSING_EMAIL/INVALID_EMAIL ข้อมูลไม่พร้อม, LATE ลงทะเบียนหลังกำหนดส่ง รายการ LATE จะไม่ส่งย้อนหลังโดยอัตโนมัติ

## การส่งจำนวนมากและข้อผิดพลาด

- ตรวจ `MailApp.getRemainingDailyQuota()` ก่อนส่ง ส่งครั้งละไม่เกิน 50 รายการ และนัดรอบต่อไปหากยังมีรายการค้าง
- เมื่อ quota หมด สถานะรวมเป็น QUOTA_EXHAUSTED และตรวจซ้ำภายในวันแจ้งเตือน ไม่อ้างว่าส่งครบ หาก quota ยังไม่พอผู้จัดต้องตรวจสถานะก่อนวันงาน
- บันทึก SENDING และ flush ก่อนส่ง เพื่อป้องกันการส่งซ้ำกรณีงานหยุดกลางคัน รายการ SENDING/ERROR ไม่ถูกส่งซ้ำโดยอัตโนมัติ ผู้จัดต้องตรวจกล่องส่งแล้ว/บันทึกก่อนเปลี่ยนกลับเป็น PENDING เพราะผู้ให้บริการอาจรับข้อความแล้วก่อนเกิดข้อผิดพลาด
- เวลาเรียก MailApp ไม่ถือ lock ของ Sheet เพื่อให้การลงทะเบียนอื่นดำเนินต่อได้ ใช้ lock สั้น ๆ เฉพาะ claim และบันทึกผล
- ไม่เปิด endpoint สำหรับส่งเมลจากสาธารณะ `doGet` คืนเฉพาะ health และ `doPost` รับเฉพาะข้อมูลลงทะเบียนที่เซ็น HMAC
