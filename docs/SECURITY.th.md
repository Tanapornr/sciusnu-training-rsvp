# ความปลอดภัยและขอบเขตของระบบ

## เส้นทางข้อมูล

```text
Browser → HTTPS /api/register (Vercel)
        → JSON ที่ลงลายเซ็น HMAC-SHA256
        → Google Apps Script /exec
        → Google Sheets ที่แชร์เฉพาะผู้จัด
```

- Browser ส่งเฉพาะข้อมูลฟอร์ม, request ID และช่องดัก bot ไม่มี Apps Script URL, secret, signature หรือ Sheet ID
- `APPS_SCRIPT_SECRET` อยู่ใน Vercel environment variables เท่านั้น ส่วน Apps Script เก็บค่าเดียวกันใน Script Properties ชื่อ `SHARED_SECRET`
- ลงลายเซ็นข้อความ `timestamp + "." + payload` โดย `payload` เป็น JSON string ต้นฉบับ Apps Script ตรวจลายเซ็นก่อนอ่าน/เขียน Sheet และรับเวลาคลาดเคลื่อนไม่เกิน 5 นาที
- การ replay ภายในช่วงเวลานี้ด้วย request ID เดิมคืนผลเดิม ไม่เพิ่มแถว เปลี่ยนข้อมูลแต่ใช้ ID เดิมจะถูกปฏิเสธ
- หาก secret รั่ว ผู้ที่ได้ secret สามารถสร้างคำขอที่ถูกต้องได้ ต้องเปลี่ยนทั้งสองฝั่งพร้อมกันและ redeploy Vercel

## การตรวจข้อมูลและการตอบกลับ

- ตรวจ allowlist คำนำหน้า/สังกัดทั้ง client, Vercel และ Apps Script จำกัดชื่อ 4–120 ตัวอักษร ต้องมีชื่อกับนามสกุล ไม่ยอมรับสูตร/HTML
- รับเฉพาะ JSON, จำกัดขนาด request 8 KiB ใน Function, ตรวจ UUID v4 และ honeypot
- ตรวจ Origin จาก allowlist แบบ exact เป็นการลดคำขอข้ามเว็บไซต์ ไม่ใช่ระบบยืนยันตัวบุคคล ผู้เรียกแบบโปรแกรมสามารถปลอม Origin ได้
- ใช้ `textContent` แสดงผล ไม่มี `innerHTML` จากข้อมูลผู้ใช้
- Spreadsheet cells ตั้งเป็น text และ escape อักขระนำที่อาจเป็นสูตร
- ผลสำเร็จออกเมื่อ Apps Script ยืนยันรหัสที่ถูกต้องแล้วเท่านั้น ไม่ใช้ `no-cors` และไม่ถือว่า HTTP 200 เพียงอย่างเดียวแปลว่าบันทึกสำเร็จ
- ไม่ log ชื่อ, สังกัด, secret, URL ปลายทาง หรือ payload ในโค้ด ส่วนข้อความผิดพลาดภายในไม่ส่งให้ browser
- ไม่มี API เปิดอ่านรายชื่อ ไม่มีจำนวนผู้ลงทะเบียนจริงแสดงสาธารณะ หน้าตรวจสถานะ Apps Script ส่งเพียง service/version
- CSP และ security headers กำหนดใน `vercel.json` ไม่โหลด fonts, scripts หรือ analytics จากผู้ให้บริการภายนอก

## การป้องกันข้อมูลซ้ำ

คีย์ใช้ hash ของชื่อที่ปรับ Unicode/ช่องว่าง/ตัวพิมพ์ + วันงาน โดยไม่ใช้คำนำหน้าหรือสังกัด ตรวจชื่อในแถวเก่าด้วยเพื่อรองรับคีย์รูปแบบเดิม ไม่แก้หรือลบข้อมูลเดิม ชื่อและนามสกุลเหมือนกันอาจเป็นคนละคน ต้องตรวจโดยผู้จัด ไม่มีการอ้างว่าระบุบุคคลได้แน่นอน และ hash ไม่ใช่การเข้ารหัสข้อมูลส่วนบุคคล

LockService ครอบการอ่าน ตรวจ และเขียน ทั้งการส่งพร้อมกันและ retry จึงไม่อาศัย cache เป็นแหล่งข้อมูลหลัก ห้ามแก้ลบคีย์ใน Sheet เองโดยไม่ตรวจสอบผลกระทบ

## การลด spam และข้อจำกัด

- Apps Script CacheService จำกัดแบบ best effort **120 รายการใหม่ต่อ IP hash ต่อช่วงเวลา 10 นาที** การส่งสำเร็จซ้ำด้วย ID เดิมไม่กินโควตา
- ไม่เก็บ IP จริงใน Sheet; Function ทำ HMAC จาก IP ที่ Vercel เติมใน `x-vercel-forwarded-for` ก่อนส่งให้ Apps Script และใช้เพียงใน cache
- Cache อาจถูกล้างก่อนกำหนดและช่วงเวลามีขอบ จึงไม่ใช่ rate limiter แบบรับประกัน เครือข่ายมหาวิทยาลัยอาจมีหลายคนแชร์ IP เดียวกัน
- หากไม่มี trusted IP header จะใช้ bucket ร่วม `unknown` ระบบยังทำงานได้แต่จำกัดผู้ใช้ร่วมกัน ไม่เชื่อ `x-forwarded-for` ที่ผู้เรียกอาจกำหนดเอง
- HMAC ป้องกันการเขียน Sheet โดยไม่รู้ secret แต่ **ไม่ป้องกันคนเรียก public `/api/register` ด้วยข้อมูลที่ผ่าน validation** เว็บนี้เป็นระบบลงทะเบียนสาธารณะ ไม่มี login, CAPTCHA หรือการยืนยันอีเมล
- ใช้ Vercel Firewall/rate limiting ก่อนถึง Function หากมีการใช้งานจำนวนมาก และเพิ่ม CAPTCHA ฝั่ง server หรือยืนยันตัวตนหากต้องการความมั่นใจสูงขึ้น
- Apps Script มี execution/quota limits และอ่านทะเบียนทั้งหมดเพื่อตรวจซ้ำ จึงเหมาะกับงานขนาดเล็กถึงปานกลาง หากปริมาณเพิ่มมากควรใช้ฐานข้อมูลที่มี unique constraint

## ข้อมูลผู้เข้าร่วม

ข้อความหน้าฟอร์มแจ้งวัตถุประสงค์จัดทำรายชื่อและประสานงาน ผู้จัดควรกำหนดผู้เข้าถึง ระยะเก็บรักษา ช่องทางติดต่อเพื่อแก้ไขข้อมูล และนโยบายของหน่วยงานก่อนเผยแพร่ ยังไม่ได้เพิ่มอีเมล/เบอร์โทรหรือสถานที่ที่ไม่ได้รับจากผู้จัด

ใช้ production และ preview คนละ Sheet/secret ห้ามส่งทะเบียน, environment files หรือหลักฐานที่มีรายชื่อเข้า GitHub และลบข้อมูลเมื่อหมดความจำเป็นตามแนวทางหน่วยงาน
